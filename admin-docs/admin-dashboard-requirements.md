# 管理后台 Dashboard 需求文档（给 AI 开发）

## 1. 文档目标

定义管理后台 Dashboard 的完整需求，包括：
- 统计指标
- 图表清单
- 数据口径
- 筛选维度
- 接口约定
- 刷新与性能要求

本文件用于前后端协同实现 Dashboard，不依赖既有后端代码。

---

## 2. 页面结构

Dashboard 由 6 个区域组成：

1. 全局筛选栏
2. 核心 KPI 卡片区
3. 趋势图区
4. 业务分布图区
5. 风险与待办区
6. 快捷入口区

---

## 3. 全局筛选条件

所有图表和统计默认跟随全局筛选：

- 时间范围：今日、昨日、近7天、近30天、自定义
- 对象范围：全站 / 指定绑定关系 / 指定用户（可选）
- 统计粒度：按日、按周、按月
- 时区：固定 `Asia/Shanghai`

说明：
- 默认时间范围为“近7天”。
- 切换筛选后，所有模块同步刷新。

---

## 4. 核心 KPI 卡片需求

## 4.1 用户指标

- 新增用户数（`users.created_at`）
- 活跃用户数（定义：当日有任务、签到、消息、内容行为任一）
- 封禁用户数（`users.status` 为封禁态）

## 4.2 任务指标

- 任务发布数（`tasks.created_at`）
- 任务完成数（`tasks.status = completed`）
- 任务完成率（完成数 / 发布数）
- 待审核任务数（按业务状态定义）

## 4.3 商城与兑换指标

- 商品兑换总次数（来自 `item_transactions` 或兑换业务）
- 兑换码使用数（`reward_codes.status = used`）
- 兑换码使用率（used / 总发放）
- 核销次数（`item_redemption_records`）

## 4.4 资产指标

- 积分消耗总额（`point_transactions.amount < 0` 绝对值求和）
- 万能卡消耗总额（`card_transactions.amount < 0` 绝对值求和）
- 异常资产变动数（规则见第 8 节）

## 4.5 内容治理指标

- 新增动态数（`bind_moments.created_at`）
- 新增日记数（`diary_entries.created_at`）
- 被处理违规内容数（治理动作统计）

## 5. 图表清单（必须实现）

## 5.1 趋势图（折线图）

### 图表A：用户增长趋势
- X 轴：日期
- Y 轴：数量
- 系列：新增用户、活跃用户

### 图表B：任务趋势
- 系列：任务发布数、任务完成数、任务完成率（右轴百分比）

### 图表C：资产消耗趋势
- 系列：积分消耗、万能卡消耗

## 5.2 分布图（柱状图/条形图）

### 图表D：任务状态分布
- 维度：`pending/accepted/completed/cancelled`
- 值：任务数量

### 图表E：兑换码状态分布
- 维度：`unused/used/voided`
- 值：数量

### 图表F：反馈工单状态分布
- 维度：`pending/processing/resolved/closed`
- 值：数量

## 5.3 占比图（饼图/环形图）

### 图表G：奖励类型占比
- 维度：`points/prop/special`
- 值：使用次数或发放次数

### 图表H：内容类型占比
- 维度：动态、日记、评论
- 值：新增条数

## 5.4 排行榜（Top N 表格）

### 榜单I：高活跃用户 Top 10
- 字段：用户ID、昵称、活跃行为次数

### 榜单J：高发布任务用户 Top 10
- 字段：用户ID、昵称、任务发布数、完成率

### 榜单K：高频兑换用户 Top 10
- 字段：用户ID、昵称、兑换次数、核销次数

---

## 6. 风险与待办模块

## 6.1 风险告警卡片

- 高频兑换告警（短时大量兑换）
- 异常资产变动告警（单用户短时大额变动）
- 违规内容激增告警（内容处理量超阈值）

每条告警展示：
- 告警类型
- 触发时间
- 触发对象
- 告警说明
- 处理状态（未处理/处理中/已处理）

## 6.2 待办事项清单

展示运营待办：
- 待审核任务数量
- 待处理反馈数量
- 待处理违规内容数量
- 待确认配置变更数量

每条待办支持点击跳转到对应管理页面。

---

## 7. 数据口径定义（必须固定）

为避免前后端口径不一致，统一如下：

- “新增用户” = 时间范围内 `users.created_at` 落入区间的去重用户数。
- “活跃用户” = 时间范围内在任一行为表有记录的去重用户数。
- “任务完成率” = `completed任务数 / 发布任务数`，分母为0时返回0。
- “积分消耗” = `point_transactions.amount < 0` 的绝对值总和。
- “万能卡消耗” = `card_transactions.amount < 0` 的绝对值总和。
- “兑换码使用率” = `used数量 / reward_codes总数`，分母为0时返回0。
- “趋势统计时间桶”按自然日/周/月，不跨时区。

---

## 8. 异常判定规则（初版）

- 高频兑换：同一用户 10 分钟内兑换次数 >= 5。
- 大额积分变动：单笔积分变动绝对值 >= 1000。
- 大额卡片变动：单笔卡片变动绝对值 >= 20。
- 内容异常激增：单日违规处理量 > 最近7日均值的 3 倍。

以上阈值需要可配置（建议落地到 `system_config`）。

## 9. Dashboard 接口约定

统一前缀：`/api/admin/v1/dashboard`

## 9.1 概览接口

- `GET /api/admin/v1/dashboard/overview`
- 用途：返回 KPI 卡片数据

响应示例：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "newUsers": 23,
    "activeUsers": 118,
    "taskPublished": 64,
    "taskCompleted": 41,
    "taskCompletionRate": 0.6406,
    "rewardCodesUsed": 77,
    "rewardCodeUsageRate": 0.5123,
    "pointCost": 1280,
    "cardCost": 33,
    "pendingFeedbacks": 9
  },
  "traceId": "d-001"
}
```

## 9.2 趋势接口

- `GET /api/admin/v1/dashboard/trends`
- 用途：返回折线图数据（按时间桶）

响应示例：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "buckets": ["2026-04-10", "2026-04-11"],
    "series": {
      "newUsers": [4, 7],
      "activeUsers": [25, 31],
      "taskPublished": [8, 10],
      "taskCompleted": [5, 6],
      "pointCost": [120, 180],
      "cardCost": [3, 5]
    }
  },
  "traceId": "d-002"
}
```

## 9.3 分布接口

- `GET /api/admin/v1/dashboard/distributions`
- 用途：返回状态分布、类型占比

## 9.4 排行接口

- `GET /api/admin/v1/dashboard/rankings`
- 用途：返回 TopN 榜单

## 9.5 告警接口

- `GET /api/admin/v1/dashboard/alerts`
- 用途：返回风险告警列表

## 9.6 待办接口

- `GET /api/admin/v1/dashboard/todos`
- 用途：返回待办聚合与跳转链接信息

---

## 10. 前端展示要求

- 所有图表支持加载态、空态、异常态。
- 支持点击图表元素下钻（跳转到对应列表页并带筛选参数）。
- KPI 卡片显示“环比变化”（对比上一个同周期）。
- 颜色规范：
  - 正向指标上升：绿色
  - 风险指标上升：红色
  - 无变化：灰色

---

## 11. 刷新与性能要求

- 默认自动刷新间隔：60 秒（可手动关闭）。
- 全量刷新耗时目标：< 3 秒（常规数据规模）。
- 单接口响应目标：P95 < 800ms。
- Dashboard 首屏需优先加载 KPI 与待办，再加载图表。

---

## 12. 验收标准

- 图表验收：本文件定义的 A-K 图表与榜单全部可展示。
- 口径验收：同一时间范围下，图表数据与 SQL 查询一致。
- 交互验收：筛选联动、下钻跳转、刷新逻辑正确。
- 性能验收：满足第 11 节目标。
- 运维验收：告警与待办可支撑日常运营排查。
